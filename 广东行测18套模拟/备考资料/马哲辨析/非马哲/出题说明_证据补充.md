# 政常新题第二批：按 Codex 原文证据出题

第一批题（F1—F6）依据GPT的非马哲底稿出题。之后调研员（Codex）在 main 上交回了 **34 条原文证据**，内容有法律条文、施行日期和广东文件原句，核验日为 2026-11-27。另外还提出 14 个候选知识点（K 开头）。这一批题按这些证据出，专练底稿没讲到或讲得不够细的新区别。

**除下面另有规定的以外，全部照 `出题说明.md` 执行**：题型、字段格式、错项写法、不靠绝对词泄题、拿不准就进 `review`，都和第一批一样。

## 先读

1. `学习资料/政治理论常识/协作核验/调研结果索引.md`：34 条证据的一览，**“使用状态”一栏决定能怎么出题**。
2. `学习资料/政治理论常识/协作核验/整理成果/2026-11-27_给Claude的核验交接.md`：调研员建议优先练的六组关系，以及旧资料里哪些说法已经过时。
3. 任务分给你的证据文件（`协作核验/原文证据/*.md`）。每张证据卡都有几栏：
   - “文件、机关与日期”“原文与语境”“事实与核验结论”是**标准答案的依据**；
   - “官方解释”相当于底稿的 `why`，可以写进解析；
   - “相邻概念与旧资料”可以改写成错项；
   - “命题分析”是调研员建议的出法，可以参考，但要换情境。
4. 证据卡关联的底稿知识块（`非马哲政治理论与广东常识训练底稿_2026-11-27.json` 的 `records`）。另外用 grep 查 `非马哲/新题/F*.json` 里关联同一知识块的已有题，**不要和它们考同一个点**。

## 每张证据卡怎么用

- **可用**：出 1 道。卡里有两组互不相同的区别（例如“谁牵头协调”和“宣传周在哪一周”）时，可以出 2 道，但两道要考不同的点。
- **限定使用**：照样出题，但题干或 `condition` 要写明限定条件。例如“已公布、2027年1月1日起施行”“《广东省国民经济和社会发展第十五个五年规划纲要》”“河源市实施口径”。脱离限定条件答案就不唯一的说法不能设成对项。
- **待补实体依据**（E-YF-03、E-YF-04）：只能考已经核实的立法动作（调研、草案说明、列入立法计划征求意见稿），不能考条例的实体内容，不能断言已通过或未通过。先看 `F5.json` 的 F-LAW-030-1、030-2，已经考过的点不要再出。
- 证据卡写明“低优先”或“会后细节”的，最多出 1 道。

## 时间口径

- 所有题以 **2026年11月27日** 为“现在”，题干写“截至2026年11月27日”或写明具体日期。
- 分清通过、公布、施行，分清“已公布未施行”和“已施行”；国家法律和广东地方性法规分开写。
- 年度目标、五年目标、阶段目标、已实现的成果分开；国家文件和广东省文件要写全称。

## 新知识点（K 编号）

有些证据卡的知识点写的是 K 开头的候选编号（如 K-LAW-01），底稿里还没有这个块。分给你的每个 K 编号，都先写一个知识块，存到 `非马哲/新题/K_<你的编号>.json`（数组），格式照底稿 `records`：

```json
{
 "id": "K-LAW-01",
 "module": "LAW",
 "title": "港澳律师在大湾区内地九市执业：考试、资质、地域、业务",
 "priority": "A",
 "correct": ["只写证据卡“原文与语境”“事实与核验结论”能直接支持的句子，写明文件、机关和日期"],
 "why": "官方解释或理解提示，没有就留空",
 "contrasts": [{"wrong": "易错说法", "reason": "错因", "correction": "改正"}],
 "question_design": "出题边界，例如必须写明哪个文件、哪个日期",
 "related_ids": ["GD-010", "LAW-002"],
 "source_ids": ["E-LAW-01"],
 "date_scope": "截至2026-11-27；适用地域、版本"
}
```

- `module`：法律类用 LAW，广东事项用 GD，党建用 P3，规划与制度用 P4。
- `priority`：调研员交接里“建议先整理的六组关系”涉及的写 A，其余写 B；在回报里说明理由。
- K 块的题，`knowledge_ids` 写 K 编号，也可以并列关联的底稿块。

## 题目字段的不同之处

- `id`：`F-<主知识块编号>-<序号>`。主知识块是底稿块时，序号**从 5 开始**，避免和第一批撞号（例如 `F-LAW-008-5`）；是 K 块时从 1 开始（例如 `F-K-LAW-01-1`）。
- `source_ids`：写证据编号（如 `"E-LAW-02"`）。底稿来源编号也能支持时可以并列。
- `origin`：写 `自编`。
- `explain`：最后用一句话点明“依据：E-xxx（文件名、条次）”。
- 证据只说到某一步的（例如“调研员只核到会议报道”），按那一步出题，不要往前推。

## 交付

- 题目：`非马哲/新题/<你的编号>.json`；K 知识块：`非马哲/新题/K_<你的编号>.json`（没有 K 编号就不写）。
- 写完自己逐题再做一遍；用脚本检查 JSON 能解析、字段齐全、`knowledge_ids` 都在底稿或你的 K 文件里、`source_ids` 都是存在的证据编号或底稿来源编号。
- 不要 git 提交。回报：题数、各题型数、答案分布、每张证据卡对应的题号、K 块列表和档次、放进 `review` 的题和理由、拿不准的题；以及你发现的**证据之间、或证据与底稿之间的矛盾**。
