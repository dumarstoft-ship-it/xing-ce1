# 非马哲政常新题：出题说明

用户要在省考政治理论和常识题上尽量全对。GPT整理了一份非马哲训练底稿，交给Claude做成训练题，并入现有的“马哲辨析日课”网页。你的任务是按本说明，从底稿的知识块出题。

## 先读

1. 底稿：`学习资料/政治理论常识/非马哲政治理论与广东常识训练底稿_2026-11-27.json`（`records` 是133个知识块，`sources` 是来源；同名 `.md` 是可读版，内容相同）。只看任务分给你的知识块，以及它们 `related_ids` 指向的块。
2. GPT写给Claude的要求：`学习资料/政治理论常识/给Claude的网页训练说明_非马哲.md`。其中“特别防错”一节全部适用，下面只摘要点。
3. 广东真题的出法：`广东/行测/2022-2026/GD2024.jsonl`、`GD2025.jsonl`、`GD2026.jsonl` 的第1—15题。照它们的问法、长度、陷阱出，但**不要复刻**这些原题（用户已经做过）。

## 每个知识块怎么用

- `correct`：已核实的知识，是标准答案的唯一依据。
- `why`：帮助理解的解释，可以写进解析，**不能**拿来当唯一的历史原因或政策动机设答案。
- `contrasts`：错误说法、错因、纠正。可以改写成错项，但要换说法、换情境，不要照抄。
- `question_design`：底稿建议的出法和禁区，必须遵守。
- `exam_eligible` 为 false 的块（P1-13）不出题。

## 出多少

- A档、B档的每个块各出**1道**；任务里列出的“本轮新增”块再多出**1道变式**，两道要换情境或换题型，不能只是换个说法。
- C档不出，除非任务另有交代。
- 一道题可以连几个块（`knowledge_ids` 全列上），但每个块都要有以它为主的题。

## 题型（照GPT的要求，以前三种为主）

- **判断并纠错**：一句话。错误题只错一处，`fix` 写改正后的完整句子。正确、错误大致各半。
- **情境单选**：给一个新情境或一段材料，问“最符合”“说法正确/错误的是”，答案唯一。“最符合”比的是题干侧重点，别的选项未必本身错，解析要说清。
- **多选逐项**：引言加设问，4个选项，答案2—4个。每项单独有理由。
- **配对、排序**：会议、著作、事件与内容配对，或按时间排序，做成单选（如“下列配对正确的是”“按时间先后排列正确的是”）。
- 精确名称题少量即可，不要整句挖空。

## 必须遵守（摘自GPT的要求）

- 范围只限底稿 `records`；不出马哲原理辨析、经典马政经全套、泛科技和桥梁航天工程清单。H18只许出作品索引题（哪年、谁写的、叫什么），不能借它出马哲原理题。
- 法律题写明适用地域、版本和必要日期，分清立法计划、草案、审议、通过、公布、施行；不能把转载日期当生效日，不能把计划或草案当成生效的法律。
- 跨文件措辞不同的，题干写明文件名和年份。P2-08（教科人才的基础、根本）、P2-16和GD-004（产业名单归类）、GD-011（合作平台定位）**不能脱离来源设唯一答案**，照各块的 `question_design` 出。
- “初次违法”不等于“必须不罚”，“封存”不等于删除或免罚，“不执行拘留”不等于没有违法责任；法典不在普通法律之上；行政法不等于行政法规；党的领导与国家机关的法定职责分开，人大、政府、政协、法院、检察院、监委按权限和动作区分。
- 每个错项都要指出被替换的是什么：主体、条件、阶段、层级、动作还是关系。
- 不能靠绝对词（所有、只要、必然）泄题：绝对词要同时出现在对的和错的说法里；选项长短、正确项位置、措辞风格要均衡。
- 拿不准、离开补充假设就答不唯一的题，先改；改不好就在 `review` 里写明理由（进待审区，不计分），不要猜一个答案。
- 真题、改编、自编要分开写在 `origin` 里；仓库里的参考答案不是官方答案。

## 交付

写成一个JSON数组，存到任务给的路径（`广东行测18套模拟/备考资料/马哲辨析/非马哲/新题/<你的编号>.json`），每题一条：

```json
{
 "id": "F-LAW-014-1",
 "module": "LAW",
 "knowledge_ids": ["LAW-014"],
 "source_ids": ["LAW-S02", "LAW-S07"],
 "type": "单选",
 "form": "情境单选",
 "lead": "材料或引言，没有就留空",
 "stem": "设问句，含“（）”；判断题就是那一句话",
 "options": [
  {"text": "选项文字", "correct": true, "why": "为什么对"},
  {"text": "选项文字", "correct": false, "why": "错因：把……换成了……（被替换的主体、条件、阶段、层级、动作或关系）"}
 ],
 "answer": "",
 "fix": "",
 "explain": "一两句总的要点：正确关系是什么",
 "condition": "适用地域、版本、日期、文件名等限定（法律题、文件口径题必填，其他可空）",
 "origin": "自编",
 "review": ""
}
```

- `id`：`F-<知识块编号>-<序号>`，序号从1起；变式用2。
- `type`：判断、单选、多选。`form`：判断并纠错、情境单选、多选逐项、配对、排序、精确名称。
- 判断题：`options` 为空数组，`answer` 写“正确”或“错误”，错误题必填 `fix`；错因写进 `explain`。
- 单选、多选：`answer` 留空（网页按 `options` 里的 `correct` 判分，并会打乱选项顺序，所以解析**不要写“A项”“B项”**，理由写在每个选项的 `why` 里）。单选恰好1个 `correct`，多选2—4个。
- `source_ids` 用底稿 `sources` 里的编号，取自所依据知识块的 `source_ids`。
- 写完自己逐题再做一遍，确认答案唯一；用脚本检查JSON能解析、字段齐全、知识块编号都在底稿里、每个任务块都有题、答案分布均衡。
- 不要提交（git）。完成后回报：题数、各题型数、答案分布、每个块的题号、放进 `review` 的题和理由、你拿不准的题。
