# 政常新题第二批：盲做核对说明

第二批题（F7、F8、F9）按调研员（Codex）交回的原文证据出题，专练底稿没讲到或讲得不细的新区别。除下面列出的不同之处，全部照 `核对说明.md` 执行。

## 与第一批的不同

1. **盲做输入没有“适用条件”**。网页上用户作答时只看到导语、设问和选项，条件栏要等作答之后才显示。所以你看到的就是用户看到的。答案唯一要靠题干没写的文件、年份、日期、地域时，在 doubt 里写明缺了什么。
2. **依据多了原文证据**：`学习资料/政治理论常识/协作核验/原文证据/*.md`（34 张证据卡，E 开头编号）。每张卡里，“文件、机关与日期”“原文与语境”“事实与核验结论”是标准答案的依据。“使用状态”看 `协作核验/调研结果索引.md`：
   - “限定使用”的卡，题干必须写明限定条件；
   - “待补实体依据”的卡（E-YF-03、E-YF-04），只能考已核实的立法动作。
   底稿 `非马哲政治理论与广东常识训练底稿_2026-11-27.json` 也照样可以查。
3. **以 2026年11月27日为“现在”**。已公布未施行的法律（2027-01-01施行的几部），除非题干写明“根据已公布、将于……施行的……”，不能拿它的条文当现行规定。

## 还要审 K 知识块

出题人把证据里的候选知识点写成了知识块（`非马哲/新题/K_<出题人编号>.json`，编号 K 开头），网页上会和底稿知识块一样显示，给用户复习用。**盲做全部写完之后**再打开它们，逐块对照证据卡检查：

- `correct` 的每一句有没有证据原文支撑；有没有把“限定使用”写成无条件结论，有没有把计划、草案写成已生效；
- `contrasts` 的错误说法、错因、纠正是否成立；
- `priority`、`question_design` 是否合理。

结果写成 JSON 数组，存到 `非马哲/核对/K核对_<你的编号>.json`，每块一条：

```json
{"id": "K-LAW-01", "verdict": "采用|需改|删除", "detail": "依据或问题", "fix": {"correct": ["改后的完整句子"]}}
```

`fix` 只在“需改”时写，写改后的完整字段。

## 交付

- 盲做结果：`非马哲/核对/check_<你的编号>_<出题人编号>.json`，格式同第一批。
- K 块审核：`非马哲/核对/K核对_<你的编号>.json`。
- 回报：各批题数、标了 doubt 的题和理由、最拿不准的题、K 块各自的结论。不要 git 提交。
