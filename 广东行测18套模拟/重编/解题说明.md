# 解题与归类说明（重编用）

## 这一步要做什么

各套模拟卷的第31—90题整段采用粉笔广东模考某一季的原题（M01对第16季，M02对第17季，……M18对第33季）。模考题库没有答案，需要独立解出每道题的答案，写给考生看的解析，按广东真题的分类归类，并找出题目本身的问题。

结果直接用于考生的答案与解析，并决定哪些题要换。答案错一道，考生就会被误导，所以答案要可靠，拿不准就如实说拿不准。

## 先盲解，后对照

1. 只看 `输入/<模块>.json`（或同名 .md，内容相同）做题。题图是PNG，路径在题面里，用Read工具看图。
2. 全部做完后，先把盲解答案写进 `解题/<模块>_blind.json`：`{"<题目id>": "A", ...}`。
3. 写完盲解文件后，才可以打开 `输入/prior.json`。那里是这些题在旧卷里用过时的答案和解析（不是每题都有，也不保证对）。不一致的题要重新核对，查清谁对，写明理由。

## 每道题交什么

写入 `解题/<模块>.json`，格式是一个列表，每题一项：

```json
{
  "id": "gd-mock-2026h2-s16-q31",
  "number": 31,
  "answer": "C",
  "category": "数字推理",
  "subcategory": "递推",
  "form": "",
  "analysis": "给考生看的解析",
  "verification": "怎样核验的；用了脚本就写脚本路径",
  "confidence": "high",
  "prior_answer": "C",
  "prior_note": "与旧卷一致 / 旧卷答案为X，错在……",
  "issues": [],
  "replace_recommended": false,
  "difficulty": "中"
}
```

- `confidence`：high（推导和复核都清楚）、medium（有一处判断不完全确定）、low（拿不准）。不要为了好看都写high。
- `issues`：题目本身的问题，比如转写错字或漏条件、数据前后矛盾、题图看不清、两个选项都对或没有正确选项、设问有歧义。没有就留空。只是难或偏，不算问题。
- `replace_recommended`：题目有上面那类硬伤、改不了就换时写true，并在issues里说清。
- `difficulty`：易、中、难，按考场上一般考生的感受估计。
- `prior_answer`、`prior_note`：prior.json里没有这题就写null。

## 解析怎么写

公考是抛球接球，不是数学考试：命题人在题面上留了提示（球），考生要看见、接住；好题的错误选项，就是漏接了某个球的人会选的答案。解析要让考生下次遇到同样的信号能想到同样的做法。所以每题解析分三段，每段另起一行（M01—M05的解析已按这个写法改写，见 [解析改写/改写说明.md](解析改写/改写说明.md)）：

```
题眼：一句话，指出本题题面上具体的提示（数字特征、问法、选项差距、限定词、设问口径……），以及它指向的做法。
推导：列式、推理或排除，得出答案。
易错：按什么错误思路会选到哪一项。（数量、资料题要算出那条错误思路确实落在点名的选项上才写；没有典型陷阱的题可以不写这一段。）
```

- 题眼要具体到本题：写“题干问‘至少’，且四个选项相差1，提示要构造最不利的情况”，不写“本题考查最值问题，需要认真分析”。
- 给考生看。篇幅与常见的机构解析相当，最多长一半；计算题写出列式和必要的估算。
- 不写编辑过程和审核的话：不出现“原题”“题库”“转写”“复核”“旧卷”“Claude”“GPT”等字样，不写“本题有争议”。这些写进issues或prior_note。
- 资料分析写清用到的材料位置和公式，估算要说明为什么能估、估到哪一位能区分选项。
- 图形推理说清规律或空间关系，并说明怎样排除其他选项。
- 逻辑题说清题型、论点论据或推理链条，以及每个选项为什么对或错（至少说清正确项和最有迷惑性的错项）。

## 核验

- 数量关系、资料分析、科学推理里能算的，用Python脚本核算，脚本放在 `解题/scripts/`，文件名带题号。数量题能枚举的就枚举验证唯一解。
- 资料分析按选项精度计算；选项接近时算准确值，不靠粗估定答案。
- 逻辑题按选项逐一检验；分析推理题枚举所有可能情形验证“一定为真”等说法。
- 图形推理逐一检查四个选项，确认只有一个符合；看不清的地方写进issues。

## 归类（与广东真题用同一套分类）

- **数字推理（31—35）**：subcategory 写 递推、多级差（作差/作商）、分数数列、幂次修正、多重数列（分组/机械拆分）、图形数阵、表格数阵、其他。
- **数学运算**：category 写 数学运算，subcategory 写 和差倍比方程（含不定方程）、行程、工程、最值与构造、排列组合与概率、经济利润、几何、杂题（日期、植树、统筹、周期等）、浓度、容斥。
- **图形推理**：category 写 规律类 或 空间类。规律类的subcategory写 位置、样式、属性、数量、立体块元素、其他；空间类写 展开与折叠（含折纸剪纸）、三视图、截面、拼合（立体拼合、平面拼合都算）、空间其他（立体图形旋转辨识等）。form 写 一组图、九宫格、分组、字符串、其他。
- **逻辑判断**：category 写 形式逻辑、论证、解释、结构比较、归纳结论。subcategory：形式逻辑分 翻译推理（条件串联、逆否即可得出）、分析推理（排序、匹配、分组、需分情况）、真假推理；论证分 削弱、加强、前提假设、论证缺陷与评价；结构比较分 推理形式或论证结构型、对话或概念错误型。
- **科学推理**：category 写 物理、化学、生物、地理；物理的subcategory写 力学、电学、光热声及其他。form 写 带图（含表格）、选项为图、无图。
- **资料分析**：category 写 资料分析，subcategory 写 比较排序、比重、增长量、增长率、现期量与简单计算、基期量、倍数、平均数、综合分析判断、材料理解（不用计算，在材料里找信息判断）、图形选项。
  - 设问要从多项中选最大、最小或排序的，subcategory 一律写“比较排序”，底层算的是什么量另写在 `basis_quantity` 字段（如“增长量”）。
  - “说法正确/错误的是”这类逐项判断题，至少一项要计算的写“综合分析判断”，都不用计算的写“材料理解”。
  - 增长率含同比、环比、年均、间隔增长率；基期量含由“低x%”“高x%”反推另一量。

## 资料分析另外要看的

- 每组材料检查一遍数据是否自洽（分项与合计、增速与绝对量），有矛盾写进该组第一题的issues，注明是否影响作答。
- 材料里标题为“图1”“图2”的表，原卷是统计图，原图没有入库，打印时会按数据重绘。请在该组第一题的 `chart_note` 字段里写一句你判断的原图形式，比如“柱状图（销量）＋折线（同比增速）”。

## 输出文件

- `解题/<模块>_blind.json`：盲解答案。
- `解题/<模块>.json`：每题完整记录。
- `解题/scripts/`：核验脚本。
- 不需要写.md报告。最后在回复里用几行话说明：答案与prior不一致的题、confidence不是high的题、建议换的题。
